1) CISC и RISC - разные подходы к созданию инструкций.
CISC
Основная идея: создание одной инструкции, которая будет выполнять почти всю работу.
Инструкции: Разной длины, сложные
Примеры: x86 (Intel, AMD), старые архитектуры (VAX, Motorola 68k).
Плюсы: Плотный машинный код (экономия памяти в прошлом), упрощение компиляторов (в теории).
Минусы: Сложный декодер инструкций, неравномерное время выполнения, большая сложность конвейеризации.

RISC
Основная идея: Набор простых, атомарных инструкций фиксированной длины, которые выполняются за один такт. Принцип "Load/Store": работа с памятью — только через специальные инструкции загрузки/сохранения, все арифметические операции — только с регистрами.
Инструкции: Фиксированной длины, простые
Примеры: ARM, RISC-V, MIPS, PowerPC, AVR.
Плюсы: Простой и быстрый декодер, глубокая конвейеризация, высокая тактовая частота, эффективное использование регистров.
Минусы: Больший размер кода (в прошлом), компилятору нужно больше инструкций для сложных операций.

Современная реальность: границы стираются используются: на одних участках используют один принцип, на других другой 

Какое минимальное количество инструкций может поддерживать процессор?
Теоретически, достаточно одной инструкции, если она универсальна. Это доказано концептуально.
Однойнструкционная архитектура (OISC): Например, инструкция SUBLEQ (Subtract and Branch if Less or Equal): A = A - B; if (A <= 0) goto C. С ее помощью можно эмулировать любые другие операции (сложение, копирование, условные переходы, циклы). 


2)Пирамида памяти (Иерархия памяти)
Это структура, организованная по принципу компромисса между скоростью, емкостью и стоимостью.

Регистры процессора: ~1 КБ, 0.2-0.5 нс, самые быстрые и дорогие.
Кэш-память (L1, L2, L3): ~КБ-МБ, 0.5-10 нс, быстрая, SRAM.
Оперативная память (ОЗУ, DRAM): ~ГБ, 50-100 нс, основная рабочая память.
Внешняя память (SSD/HDD): ~ТБ, 0.1-10 мс, постоянное хранение.

Чем выше уровень, тем меньше, быстрее и дороже память. Процессор работает с данными на верхних уровнях, а при их отсутствии данные поднимаются с нижних уровней.

Кэши процессора
Это небольшая сверхбыстрая память SRAM, служащая буфером между ядром и медленной DRAM. Принципы работы:

	Локаличность обращений:

		Временная: Если к данным обратились, скоро обратятся снова. (Копируем данные в кэш.)

		Пространственная: Если к данным обратились, скоро обратятся к соседним. (Кэшируем не один байт, а целый блок/строку кэша.)

	Уровни: L1 (разделен на инструкции и данные, самый быстрый), L2 (обычно на ядро), L3 (общий для всех ядер, самый медленный из кэшей).


SRAM vs DRAM

SRAM (Статическая): Ячейка: 6 транзисторов (триггер), Плотность: Низкая, дорого, Скорость: Очень высокая (кэши), Потребление: Больше (постоянно включены), Статичность: Сохраняет данные, пока есть питание, Где используется: Кэш-память процессора (L1-L3)

DRAM (Динамическая): Ячейка: 1 транзистор + 1 конденсатор, Плотность: Высокая, дешево, Скорость: Относительно медленная (ОЗУ), Потребление: Меньше (но требует регенерации), Статичность: Конденсатор разряжается, нужна регенерация, Где используется: Основная оперативная память (ОЗУ)


3)Отличие от других знаковых представлений:

Прямой код: Старший бит — знак (0 = '+', 1 = '-'), остальные — модуль числа. Недостаток: Два нуля (+0 и -0), сложная арифметика (нужны отдельные схемы для сложения и вычитания).

Обратный код: Для отрицательных: инвертировать все биты модуля. Недостаток: Остаются два нуля, требуется коррекция переноса (циклический перенос).

Дополнительный код: Для отрицательного числа -X в N-битном представлении: 2^N - X. На практике: инвертировать все биты модуля и прибавить 1. Преимущества: Только один ноль, универсальная операция сложения для всех комбинаций знаков (не нужны отдельные схемы для вычитания). Вычитание A - B реализуется как A + (-B), где -B — доп. код B.

Как и почему работает расширение знака в доп. коде?
Расширение знака — это операция увеличения разрядности числа (например, с int16_t на int32_t) без изменения его значения.

Правило: Скопировать старший (знаковый) бит во все новые старшие разряды.

Пример (8 -> 16 бит):

+5 = 0000 0101 -> 0000 0000 0000 0101

-5 = 1111 1011 -> 1111 1111 1111 1011

Почему это работает?
Это напрямую вытекает из математического определения доп. кода (2^N - X).
Пусть у нас есть отрицательное число -X, представленное в N битах как A = 2^N - X.
Если мы хотим расширить его до M бит (M > N), мы должны представить то же число -X в M битах: B = 2^M - X.
Посмотрим на разность: B - A = (2^M - X) - (2^N - X) = 2^M - 2^N = 2^N * (2^(M-N) - 1).
Число (2^(M-N) - 1) в двоичной системе — это просто M-N единиц. Умножение на 2^N добавляет N нулей в младшие разряды.
Таким образом, чтобы получить B из A, нужно дописать слева (M-N) старших разрядов, заполненных единицами, что эквивалентно копированию знакового бита (который для отрицательного числа равен 1). Для положительных чисел знаковый бит 0, и расширение нулями работает по той же логике.

Итог: Механизм расширения знака позволяет прозрачно и без дополнительных операций работать с числами разной разрядности, что критически важно для эффективной арифметики.
